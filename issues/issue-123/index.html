[TASK] - Criação do realease notes v1.0.0

Com base no trabalho que acabamos de realizar (criação das Release Notes da v1.0.0, atualização do README e confirmação do Deploy/Infraestrutura), aqui está o preenchimento ideal para a abertura dessa Issue ou Task:

🎯 Objetivo / Motivação Formalizar o lançamento da versão v1.0.0 do OncoMap, consolidando a entrega do produto em ambiente de produção. Esta tarefa é necessária para comunicar aos stakeholders e usuários que o sistema atingiu a maturidade estável, documentando as funcionalidades principais (Relatórios com IA, Mapas Interativos), a infraestrutura implementada (Supabase, Deploy) e as métricas de qualidade alcançadas (>90% de cobertura de testes).

📋 Escopo da Tarefa e Entregáveis [ ] Criar/Publicar o documento de Release Notes v1.0.0 destacando o status “Deployed” e a integração com Supabase.

[ ] Link direto para o ambiente de produção (Deploy).

[ ] Badges atualizadas (Versão 1.0.0, Status Concluído, Coverage >90%).

[ ] Instruções de configuração do ambiente (Docker, Variáveis de Ambiente GROQ e QUERIDO_DIARIO).

[ ] Documentar a infraestrutura de produção (Banco de Dados no Supabase e Pipeline de CI/CD mensal) nas notas de lançamento.

[ ] Revisar e consolidar a documentação de arquitetura (Arquitetura.md) para refletir o uso do Gemini 2.0 Flash Lite e Fallback com Groq.

✅ Critérios de Aceitação [ ] O documento de Release Notes deve estar publicado no repositório (ou na aba Releases do GitHub) contendo as seções: Features, Infraestrutura (Supabase/Deploy) e Correções.

[ ] As instruções de instalação no README devem refletir a necessidade das chaves de API do Gemini e Groq.

[ ] A tag de versão no repositório deve ser v1.0.0.

[ ] A menção à cobertura de testes (>90%) deve constar na documentação de qualidade.

🔗 Dependências (Opcional) Depende da conclusão do deploy na branch main e da verificação final dos testes de integração no ambiente de produção.

💡 Sugestão de Implementação (Opcional) Utilizar o texto gerado para o Release Notes que enfatiza a transição de MVP para Produto Estável. Garantir que as seções de “Infraestrutura” deixem claro o uso do Supabase para persistência de dados e do GitHub Actions para a automação mensal da coleta de dados.
